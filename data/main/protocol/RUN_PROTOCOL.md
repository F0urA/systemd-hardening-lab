# Новые измерения v005: фиксация до данных

Дата фиксации на Windows: 12.10.2026. Этот документ и хеши замороженной
рабочей копии сохранены локально до новых измерений. Публичной независимой
предрегистрации/коммита GitHub нет; требование исходного протокола в этой части
не выполнено. Архивные результаты известны заранее и не являются новыми данными.

## Стенд и отклонения

ALT Server 11.1, Linux 6.12.74-6.12-alt1, systemd 257.9, VirtualBox 7.2.16,
4 vCPU, 4 GiB RAM. Хост AMD Ryzen 5 2600 (6 физических/12 логических ядер),
не Intel Core Ultra из архива. Маска Intel 0x3C03 неприменима. Все новые измерения
выполняются на одном текущем стенде, без объединения с архивом.
Гостевая привязка: служба CPU0, генераторы CPU1-3. Привязка процесса VirtualBox
на Windows не меняется (все 12 логических процессоров). Это отклонение от
архивного pinned-host режима. Частоты Windows — только вторичная диагностика.

Проверка часов 12.10.2026: Windows UTC epoch 1791824837, guest UTC epoch
1791801797; Windows опережает гостя на 23040 секунд (6 ч 24 мин). Часы не меняются
во время измерений. Имена гостевых каталогов относятся к гостевой шкале UTC.
Времена Windows сохраняются отдельно. Расхождение повторно проверяется в конце.
Временный запрет сна Windows действует только пока работает мониторинг.

Выход ВМ: `/root/article-experiment/20261012-v005/results_v005`.
Локальный выход: `results/raw-vm/`. Секреты, SSH-ключи и содержимое паролей
в результаты не включаются. Внешних публикаций/новых сетевых доступов нет.

## Зафиксированные условия

Исходные procedure_v005.txt и protocol_review2_v005.txt не меняются.
delta=5%, H={2,5,10,15}%, обязательные цели оператора пусты, диагностический
порядок s, Emicro, Exposure, n. Решения только по alpha=0.05/(M*2), K=2:
один добор для NEEDS_MORE_DATA, объединение новых блоков того же стенда,
затем INCONCLUSIVE, если границы не определяют исход. Никакой подгонки порогов.

Пилот: Nginx, 10 парных блоков P0/P4, N=100000 на каждого из двух генераторов,
C=25, KEEPALIVE=0. Начало основных серий разрешено только при CV(P0)<=5%.
Пилот не входит в основной анализ. Оба метронома: предел паузы 500 ms;
invalid сохраняется и повторяется максимум 5 раз. Ошибка запроса завершает
серию; возможный повтор — новая полная серия, старые файлы не удаляются.

R1: Nginx 60 блоков, P0/P1c/P4/P5/P6, два AB по 100000 запросов,C=25,M=4.
R2: Redis 20 блоков,P0/P1/P2/P1d/P4/P6,3000000 GET,50 клиентов,3 потока,M=5.
R3: PostgreSQL 10 блоков,P0/P1/P2/P1d/P4/P6,60 s,10 клиентов,2 потока,M=5.
R4: отдельный Nginx режим P0/P1c/P4,60 блоков,M=2. До основной серии
пилотировать C=1,2,4,8,16 (по 3 блока P0/P4), выбрать первое C с CPU(P0)
40–70% во всех трёх блоках. Если такого нет, R4=FAILED, не подменять режим
ограничением скорости или иным генератором.
R5 (дополнительная новая серия вместо непереносимого архивного P2): Nginx
60 блоков,P0/P1/P2/P1r,M=3. Анализ отдельный от R1; при объединённом выборе
из всех семи ограниченных профилей Nginx применять консервативное M=7 ко всем.
R5 не объединяется с архивными блоками и не заменяет основную R1.

## Функциональность и сценарии

F требует запуска И всех обязательных операций protocol_review2 §5.
Reset владельца Nginx-журнала допускается только перед отдельной ячейкой
контракта и при cleanup; не между операциями внутри F. Failed restart после
USR1 исключает профиль, даже если явная миграционная процедура помогает.
Миграция: 2 исходных профиля × 4 независимых операции, без/с явным chown root.
TLS+upstream — отдельный nginx-tls unit, не F нагрузочного порта 808.

Проверки контекстов: P0,P1,P1r,P1c,P4. Основные цели: все профили Nginx;
Redis/PG также P1,P2,P1d. Абляция capabilities отдельно, описательная.
Отсутствующая/сломанная проба=UNEXPECTED/ERROR, никогда автоматически BLOCKED.

В исходном тексте G4 противоречит правилу вывода целей (для записываемого
пути требуется чтение, но G4 проверяет запись). Сохраняем G4 как заданную
диагностическую цель; не заявляем строго независимое построение всех целей.
Секрет G2 синтетический, а не реальный секрет рабочей конфигурации.
G3 использует синтетический соседний файл, не меняет настоящий nginx.conf.

Дополнительный supplement_goals: одинаковый G1 внутри настоящего unit
(ExecStartPost master/явное переключение к worker) и отдельная попытка
унаследованного directory FD через OpenFile до sandbox. P0/P1/P1r/P1c/P2/P4/P5/P6,
2 DAC×2 контекста. Они публикуются отдельно и не дописываются задним числом
в первичную goals.csv. Неподдерживаемый inherited FD = не проверенное состояние,
не доказательство защиты. Процесс ExecStartPost не является настоящим worker;
граница переноса на скомпрометированный worker явно сохраняется.

## Исправления рабочей копии до данных

1. Отдельный ROOT; UTC в общей библиотеке; NGINX_C вместо жёсткого c25.
2. Ошибка set-u в cap_ablation устранена.
3. journal --since использует epoch, а не неоднозначный локальный час.
4. Обязательный contract.csv включён в F; ERROR/MISSING/FAIL не проходят.
5. Миграционные ячейки независимы; TLS вынесен отдельно; неуспешная операция
   не маскируется изменением владельца журнала.
6. Неполные AB counts/явные Redis errors/PG failed transactions завершают серию;
   метрономы не остаются после ошибки.
7. Goals server/model: неожиданный ответ не интерпретируется как BLOCKED.

Правило отбора, t-границы, Bonferroni-поправка и бюджеты не меняются.
Все исходные файлы и старые результаты сохраняются в immutable reference.
Новая служба memcached получает отдельную фиксацию параметров до её подготовки.
