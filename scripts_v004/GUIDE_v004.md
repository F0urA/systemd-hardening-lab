# Как воспроизвести эксперимент (v003)

Порядок ниже — тот, в котором эксперимент был выполнен 11.10.2026. Что получилось, какие были отклонения и находки, записано в `results_v004/report_v004.md`.

## Что нужно

- Чистая установка ALT Server 11.1 в виртуальной машине: 4 виртуальных процессора, около 4 ГБ памяти, доступ в интернет к репозиторию пакетов.
- Вход под root.
- Для нагрузочных серий — хост, на котором машина не переезжает между ядрами разного типа и не уходит в режим ожидания. На ноутбуке с гибридным процессором машина была привязана к производительным ядрам (маска задаётся процессу `VBoxSVC`, машина наследует её при запуске).

## Порядок

Каталоги `scripts_v004` и `stand_v004` копируются на стенд рядом друг с другом, например в `/root/v003`. Все команды выполняются из `scripts_v004`.

| Шаг | Команда | Меняет службы | Результат в `/root/systemd-lab-results` |
|---|---|---|---|
| 1. Сборка стенда | `./setup_stand_v004.sh` | создаёт их | `stand-v004.txt`, `setup-v004.log` |
| 2. Кандидаты | `./make_candidates_v004.sh`, `./make_ablation_v004.sh` | нет | `P6.conf`, `P4s.conf`, `P4n.conf` в каталогах профилей |
| 3. Микропроверки | `./probe_all_v004.sh` | нет | `probe-v004/<дата>` |
| 4. Соответствие модельного процесса реальному | `./context_compare_v004.sh` | да | `context-v004/<дата>` |
| 5. Пилот нагрузки | `NGINX_N=100000 ./benchmark_v004.sh nginx 10 P4` | да | `nginx/benchmark-v004/<дата>` |
| 6. Фиксация протокола | коммит `protocol_v004.txt` и `protocol_load_v004.txt` | — | — |
| 7. Цели нарушителя | `./scenarios_v004.sh` | да | `scenarios-v004/<дата>` |
| 8. Расширенная функциональная проверка | `./functional_ext_v004.sh` | да | `functional-v004/<дата>` |
| 9. Нагрузочные серии | см. ниже | да | `<служба>/benchmark-v004/<дата>` |
| 10. Причина роста затрат | см. ниже | да | `nginx/benchmark-v004/<дата>` |
| 11. Таблица критериев и выбор | см. ниже | нет | `criteria_*.csv`, `selection_*.txt` |
| 12. Лестница профилей | `./ladder_check_v004.sh` | да | `ladder-v004/<дата>` |

Скрипты, меняющие службы, требуют исходного состояния стенда (три службы под сохранённым P4, других drop-in нет) и возвращают его при выходе.

После перезагрузки машины процессы-мишени нужно запустить вручную:

```
for u in labweb labredis labpg root; do systemctl start lab-proc-target@$u; done
```

### Шаг 5. Условие запуска серий

Серии запускаются, только если коэффициент вариации P0 в пилоте не выше 5 %. В `run.log` значение `CPU_PCT` должно быть выше 90: это признак того, что узкое место — сервер.

### Шаг 9. Нагрузочные серии

```
NGINX_N=100000 ./benchmark_v004.sh nginx 20
REDIS_THREADS=3 REDIS_N=3000000 ./benchmark_v004.sh redis 20
PG_T=60 ./benchmark_v004.sh postgresql 10
```

В конце каждой серии печатается проверка для каждого кандидата: `PRIMARY_NONINFERIORITY_95` и `CPU_PER_OP_ONE_SIDED_95_UPPER_INCREASE`. Строка `INVALID MEASUREMENTS REPEATED` показывает, сколько измерений повторено из-за пауз виртуальной машины.

### Шаг 10. Причина роста затрат

```
NGINX_N=100000 ./benchmark_v004.sh nginx 20 P4 P4s P4n
python3 ablation_report_v004.py <каталог серии>/results.csv
```

### Шаг 11. Таблица критериев и выбор

```
R=/root/systemd-lab-results
python3 build_criteria_v004.py --probe $R/probe-v004/<дата> --scenarios $R/scenarios-v004/<дата> \
  --bench nginx=$R/nginx/benchmark-v004/<дата основной серии> \
  --bench redis=$R/redis/benchmark-v004/<дата> \
  --bench postgresql=$R/postgresql/benchmark-v004/<дата> --out $R/criteria.csv
python3 select_profile_v004.py $R/criteria.csv --budgets 2,5,10,15
```

Для Nginx указывается каталог основной серии, а не серии шага 10.

## Дополнительные расчёты

- `pool_series_v004.py` — объединяет две серии в один файл с последовательными номерами блоков (расчёт по 40 блокам).
- `freq_adjust_v004.py` — разведочный расчёт с поправкой на частоту процессора хоста; нужен журнал состояния хоста и время окончания измерений (`results_v004/host-activity-v004`).

## Нумерация

Все файлы и каталоги имеют один номер версии — v003. Во время эксперимента исправленные скрипты временно получали номера v004 и v005; после завершения они переименованы. Соответствие прежних и нынешних имён приведено в начале `results_v004/report_v004.md`; первые редакции скриптов доступны в истории репозитория.
