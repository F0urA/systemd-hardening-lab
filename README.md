# systemd-hardening-lab

Материалы статьи «Экспериментальная оценка защитного эффекта и стоимости профилей hardening
системных служб Linux средствами systemd»: настройка служб и профили ограничений, скрипты стенда,
измерений и анализа, сырые результаты и команда, которая заново получает из них таблицы статьи.

## Что где лежит

```
README.md               этот файл
reproduce.py            пересчёт таблиц статьи из сырых данных (см. ниже)
docs/
  EXPERIMENTS_v005.md   карта: раздел статьи → скрипт и параметры → каталог с результатом
  SANITIZATION.md  что изменено при подготовке пакета к публикации
  history/              рабочие инструкции, написанные до основных измерений;
                        v003/, v004/ — редакции скриптов и стенда этапов 1–2
stand_v005/             настройка служб
  units/                unit-файлы служб Nginx, Redis, PostgreSQL и модельного процесса
  conf/                 конфигурации Nginx и Redis
  profiles/             профили ограничений systemd (P0–P6 и варианты) для каждой службы
  probes/               зонды: микропроверки изоляции и проверки целей нарушителя
  tls_v005/             конфигурация для проверки TLS
scripts_v005/           скрипты
  setup_stand_v005.sh   сборка стенда с нуля; GUIDE_v005.md — порядок запуска
  *_v005.sh, *_v005.py  измерения (нагрузка, функция, цели, абляция, монтирование) и анализ
  protocol_*.txt, procedure_v005.txt   процедура и протоколы, зафиксированные до измерений
  orchestration_v005/   очередь серий на стенде; run_stage3.sh — вся очередь этапа 3 на новом стенде
  analysis_v005/        анализ на стенде и проверки отчёта
  host_v005/            вспомогательные скрипты хоста (выгрузка результатов, монитор)
  tests_v005/           тесты
data/
  rerun/                повторение этапа 3 19–20.10.2026 очередью run_stage3.sh — все числа раздела 6 статьи
    raw-vm/             сырые результаты (7178 файлов) и манифест SHA256-CLOSED-RESULTS.txt
    analysis-first-look/, analysis-final/   первый и окончательный анализ
    memcached/, memcached-attempt1/   memcached, измеренный отдельно после опечатывания
    vm-logs/, archives/ логи фаз и раскладки, архивы с ВМ; README.md — хронология и отступления
    derived/            производные таблицы (точечные оценки, проверка PostgreSQL, обязательные цели)
  main/                 первый прогон этапа 3 (12–14.10.2026, другой хост); в статье — для сопоставления
    raw-vm/             сырые результаты (7587 файлов) и манифест SHA256-CLOSED-RESULTS.txt
    analysis-first-look/, analysis-final/   первый и окончательный анализ
    protocol/           записи фиксации до измерений: RUN_PROTOCOL.md, *_FREEZE*, архивы *-frozen.zip
    frozen-*/           распакованные копии исполнявшихся версий скриптов
    reports/            отчёт о выполнении (report_v005.md), статус, проверки полноты и чисел
    logs/               журналы выгрузки результатов и монитора хоста
    executed/           копии скриптов, исполнявшихся на хосте
    archive-retrospective/, resume-context-20261013/   пересчёт архивных серий, контекст продолжения
  derived/              производные таблицы первого прогона (точечные оценки, проверка PostgreSQL)
  preliminary/          предварительные измерения (этапы 1–2); с основными не объединяются
```

Профиль — это надстройка к unit-файлу службы: например, `stand_v005/profiles/nginx/P1c.conf`. Сырой
результат одного измерения — файл в каталоге серии, например
`data/rerun/raw-vm/nginx/benchmark-v005/20261019-172537/`: `results.csv` по всем блокам и вывод
генераторов нагрузки по каждому измерению.

## Воспроизведение расчётов

```
python reproduce.py          # оба прогона, полная проверка (несколько минут)
python reproduce.py rerun    # только данные статьи
python reproduce.py --quick  # без сверки сырых файлов с манифестами
```

Виртуальная машина не нужна. Скрипт делает следующее:
- сверяет сырые данные с манифестами; для `data/main` архивы исполнявшихся скриптов — с хешами, записанными
  до измерений; для `data/rerun` все файлы, разложенные на стенде, — с коммитом `6eb755e` (нужен клон с
  историей, а не архив репозитория);
- заново строит из принятых серий таблицу критериев (границы с поправкой, исходы добора);
- повторяет выбор по правилам A, A+ и B, 24 политики оператора и выбор с обязательными целями;
- считает прямые контрасты, точечные оценки и проверку t-границ PostgreSQL перестановочными границами;
- для `data/rerun` заново строит критерии и выбор memcached;
- сравнивает всё с сохранёнными результатами.

Нужны Python 3.9+ и numpy (только для последнего шага).

## Повторение измерений

Порядок работы на стенде описан в `scripts_v005/GUIDE_v005.md`, соответствие разделам статьи — в
`docs/EXPERIMENTS_v005.md`. Основные измерения (этап 3) на чистой ВМ ALT Server 11.1 повторяются одной
очередью, под root:

```
git clone https://github.com/F0urA/systemd-hardening-lab.git /root/src
bash /root/src/scripts_v005/orchestration_v005/deploy_stage3.sh
bash /root/systemd-hardening-lab/run_stage3.sh stand      # стенд с нуля
bash /root/systemd-hardening-lab/run_stage3.sh all        # проверки, серии, анализ, добор, memcached, архив
```

Очередь собрана после первого прогона из исполнявшихся драйверов и протокола; данные `data/rerun` получены
ею (коммит `6eb755e`), с memcached, измеренным отдельно из-за двух ошибок сравнения версии, которые после
этого исправлены (`data/rerun/README.md`). Скрипты копируются на ВМ вместе со `stand_v005/`. Значения, привязанные к
машине, задаются параметрами `SLAB_BASE`, `SLAB_SSH_HOST`, `SLAB_PYTHON`, `SLAB_SH`. На стенде
результаты пишутся в `results_v005/`; в этом репозитории они разложены по `data/`.

## Замечания

- `v005` в именах файлов и каталогов — редакция скриптов, которой выполнен эксперимент; под этими
  именами она записана в данных и протоколах фиксации, поэтому имена не меняются. Инструменты, добавленные
  после эксперимента (`reproduce.py`, `pg_contrasts.py`, `run_stage3.sh`, `deploy_stage3.sh`), номера не
  имеют. Прежние редакции (этапы 1–2) — `docs/history/v003/`, `docs/history/v004/`.
- Точные исполнявшиеся версии скриптов первого прогона лежат в `data/main/protocol/*-frozen.zip` и
  `data/main/frozen-*/`; `scripts_v005/` — их переносимая редакция с той же логикой. Повторение исполняло
  `scripts_v005/` и `stand_v005/` коммита `6eb755e`.
- Драйверы `driver_primary_v005.sh` и `driver_primary_corrected_v005.sh`, которые запускали первые
  серии, в пакет не вошли: известны только их хеши (см. `docs/EXPERIMENTS_v005.md`). Их часть очереди
  (пилот, R1, R2, R3) по протоколу восстановлена в `run_stage3.sh`.
- При подготовке пакета из записей удалены локальные пути компьютера, на котором шли измерения, а
  ссылки в отчётах переведены на новые места файлов. Сырые данные не изменялись. Перечень изменений с
  хешами до и после — `docs/SANITIZATION.md`.
